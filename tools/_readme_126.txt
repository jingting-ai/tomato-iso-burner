Doro 镜像刻录工具 v1.2.6 —— 使用说明
=================================================


【本版修复了什么（重要）】

  症状：整盘 ISO 刻录时，写到 1MB / 2MB / 6MB 处就报
        「写入设备失败（Windows 错误码 5 / 拒绝访问）」，刻录中断，
        U 盘停在半截状态，看起来像"被写坏了"。

  根因（已用日志 + 分区偏移实测闭环）：
    · 镜像自带分区表，第 1 块写入就把 U 盘旧分区表覆盖掉；
    · Windows 挂载管理器随即把镜像里的新分区（EFI 区正好从 2MB 起）
      挂载成卷；
    · Windows 会拒绝对「任何一个已挂载卷的第一个扇区」做裸写入
      → 错误码 5。报错偏移与那个分区起始偏移完全一致，一个字节不差。
    · EFI / MSR 分区没有可识别文件系统，句柄打不开、锁不上，
      所以"锁盘"这条路走不通。

  本版做法（已实测有效）：
    · 写盘前先清除目标盘分区表，盘上不再有卷对象 → 引导扇区保护失效；
    · 把含 MBR/GPT 分区表的首块推迟到整盘最后写入 → 写入全程
      盘上没有有效分区表，系统想挂也无从挂起；
    · 出错时关闭并重开物理磁盘句柄再重试（旧句柄被重挂载污染后
      继续用只会得到错误码 1）。

  实测结果：3.08GB Ubuntu ISO 整盘刻录成功，写入 100%，
  读回 SHA256 与源镜像完全一致。


【怎么确认你用的是新版】

  · 看日志第 2 行，写着「版本标记 burn-1.2.5-r7」即为最新；
  · 双击「查看当前版本.cmd」，会列出绿色版和安装版两处脚本的
    日期、大小、版本号，并告诉你是不是最新版。

  程序标题栏显示 v1.2.6。

【先搞清楚：ISO 刻录后 U 盘"看起来坏了"是正常的】

  ISO 刻录的原理是用镜像自带的文件系统（ISO9660/UDF）整盘覆盖
  U 盘原来的 NTFS/exFAT。刻完之后 Windows 资源管理器认不出这个
  文件系统，就会显示「需要格式化 / RAW / 未知容量」。

  Rufus、Etcher 烧任何 Linux ISO 都是这个结果，不是 U 盘被写坏。
  烧好的盘是「可启动盘」，不是「能往里拷文件的普通 U 盘」。

  · 只想往 U 盘拷文件 → 根本不该用刻录器，直接复制粘贴即可。
  · 想让 U 盘恢复成普通空盘（会清空数据）→ 双击「修复U盘\一键修复U盘.cmd」。
  · 刻录完成后如果弹出"是否格式化" → 点取消，不要格式化。


【刻录前请做这几件事（能避免大部分失败）】
  · 关闭所有停留在该 U 盘上的「此电脑 / 资源管理器」窗口。
  · 暂停杀毒软件的实时防护（360、火绒、Windows Defender 等）。
    部分国产杀软的「U 盘保护」会持续占用 U 盘，必须临时关闭。
  · 不要打开「磁盘管理」或任何分区工具。
  · 插在机箱后面的 USB 口（直连主板），不要用前面板或 USB Hub。
  · 刻录过程中不要拔 U 盘。


【安全性说明】
  · 程序绝不会向系统盘（Windows 所在磁盘）写入，已加硬性拦截。
  · 写入前会校验：目标句柄确实指向你选的那块物理盘、镜像放得下。
  · 写入后会立刻从 U 盘读回并比对 SHA256，不一致会明确报错。
  · 任何内部异常都会中止并提示，不会带着未知状态继续写。
