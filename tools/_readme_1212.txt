Doro 镜像刻录工具 v1.2.12 —— 使用说明
=================================================


【本版修复（重要）：25H2 镜像曾被误判成 24H2】

  ▸ 问题现象

    选一个 Windows 11 25H2 的官方镜像，识别结果却写「Windows 11 24H2」，
    版本号也停在 10.0.26100.xxxx，看着像是识别错了。

  ▸ 原因（不是你的镜像有问题，是判断依据选错了）

    Windows 11 的 25H2 和 23H2 属于「启封包」更新，它们和各自的基础版本
    24H2、22H2 共用同一套二进制文件，只是靠一个很小的功能包把版本号顶上去。

    后果就是：安装光盘里的 sources\setup.exe，25H2 的盘和 24H2 的盘报出来
    的版本号是一样的（都只报基础内核号 10.0.26100.x）。上一版正是拿这个
    setup.exe 的版本号当判据，所以对 25H2 只能得出 24H2 的结论。

  ▸ 本版的修法

    改读镜像里安装映像文件（sources\install.wim 或 install.esd）内部的真实
    版本号。这是唯一能区分启封包版本的地方 —— 25H2 的映像里写的就是
    26200，24H2 写的是 26100：

      25H2 镜像 → Windows 11 25H2   版本 10.0.26200.8037
      24H2 镜像 → Windows 11 24H2   版本 10.0.26100.xxxx

    识别结果下面那行「识别依据」会写清楚版本是从哪儿来的，例如：

      sources/INSTALL.WIM → 系统映像 10.0.26200.8037 · 置信度 98%

  ▸ 万一镜像里真的读不到系统映像

    有些自制盘、精简盘会把 install.wim 删掉，或换成读不出来的格式。这种
    情况下本版不再照文件名硬猜，而是：

      · 系统名称如实写成「Windows 11 24H2 / 25H2」，不装作能分清；
      · 置信度下调到 55%；
      · 在界面上用一行醒目提示说明「读不到系统映像，二者共用同一内核，
        无法区分」，并注明文件名里的版本记号仅供参考。

    宁可说「我不敢确定」，也不给你一个看着像真的的错答案。

  ▸ 顺带优化

    读系统映像时只读文件末尾的版本信息，不会把整个 install.wim（有的超过
    7GB）读进内存，所以识别依然在几十毫秒内完成，不占内存、不动磁盘。

【上一版修复（v1.2.11）：以管理员重启后不再多出一个窗口】

  点「以管理员重启」，新窗口起来了，但原来那个没有管理员权限的旧窗口
  还留在那儿，变成两个窗口叠着，分不清该操作哪一个。

  原因是程序没有单实例保护，提权后新旧两个进程各管各的。现在加了单实例锁：

    · 提权成功 → 旧窗口自动关闭，只留下带管理员权限的那个；
    · 用户取消 UAC 或提权被拒 → 旧窗口保持不动，并给出提示，不会白关；
    · 重复双击图标 → 不会再开第二个窗口，而是把已有的窗口提到前面；
    · 正在刻录时点提权 → 不会自动关窗口，避免打断写入。


【界面顺序、自动选写入方式、深色模式（v1.2.9 新增）】

  ▸ 镜像的识别结果在「写入方式」上面

    先看清「这是什么系统的镜像」，再决定「怎么写到 U 盘」。如果只想把磁盘
    恢复成普通空盘，第 1 步的镜像可以直接不选（此时会显示一句提示）。

  ▸ 按识别结果自动选择写入方式

    识别完成后，「模式」会自动帮你选好，并在下面标一个「自动」标签说明理由：

      · 镜像含引导信息（UEFI / BIOS ISOLINUX / Windows 引导）
          → 自动选「整盘镜像刻录」，这是做启动盘的正确做法

      · 镜像未检测到引导信息（例如 virtio 驱动盘、纯数据光盘）
          → 自动切到「非可引导（格式化）」，把 U 盘变成能正常读写的普通盘

    注意：非可引导模式不会写入镜像内容，只会把磁盘格式化。如果你其实是想把
    镜像里的文件放进 U 盘，请在模式下拉框里手动改回「整盘镜像刻录」——
    一旦你手动改过，程序就不会再自动覆盖你的选择。

    （后续版本的「ISO 模式（解包重排）」会把镜像内容解包后写进 FAT32 分区，
      那种做法才既能正常读写又能保留文件。当前版本请按需手动选择。）

  ▸ 深色模式

    右上角「外观」三态切换：

      自动（跟随系统）   跟着 Windows 的「浅色 / 深色」设置走，系统换它也跟着换
      浅色              始终浅色
      深色              始终深色

    偏好会记在本机，下次打开还是你选的那个；切换时窗口边框、滚动条、右键菜单
    也会一起换色。启动前就已确定主题，不会先闪一下白底。


【自动识别镜像里的系统版本（v1.2.8 新增，本版增强）】

  在「步骤 1」选好镜像后，程序会立刻读取镜像内容，把里面的系统信息显示出来，
  不用再靠文件名猜。识别结果包括：

    · 系统名称与版本   例如 Windows 11 25H2、Ubuntu 24.04.3 LTS "Noble Numbat"
    · 内核/版本号      例如 Windows 10.0.26200.8037、Ubuntu 24.04.3
    · 处理器架构       x86_64 (64 位) / ARM64 / x86 (32 位)
    · 是否可引导，以及引导方式（UEFI / BIOS ISOLINUX / Windows 引导）
    · 卷标、镜像格式（ISO 9660 / Joliet / UDF）、镜像大小

  识别依据来自镜像内部的真实标记，不依赖文件名，改名也认得出来：

    Windows            优先读 install.wim / install.esd 里系统映像的真实
                       版本号（能区分 25H2 与 24H2 这类启封包版本）；
                       读不到时退回 setup.exe 版本 + idwbinfo.txt
    Ubuntu / Kali /
    Debian / 国产系统  读 .disk/info、README.diskdefines
    麒麟 / 统信 /
    RHEL / Fedora /
    Rocky / AlmaLinux  读 .treeinfo
    Arch / openSUSE /
    Alpine / ESXi      读卷标与目录特征

  说明：识别过程只读镜像文件，不碰磁盘设备，不需要管理员权限，通常几十毫秒完成。


【镜像格式说明：Windows 官方 ISO 的内容在 UDF 里】

  Windows 10/11 官方 ISO 为了让 install.wim 突破 4GB 限制，把内容全部放进了
  UDF 分区，ISO 9660 部分只剩下一个 README.TXT。本工具含 UDF 解析，
  所以这类镜像同样能正确识别。


【写入方式（v1.2.7 新增）】

  第 1 步的「写入方式」下拉框，两种模式：

  ① 整盘镜像刻录（DD 模式）
     把镜像按字节原样写入磁盘，镜像自带的分区表、引导扇区、文件系统全盘照搬。
     做 Linux 启动盘用这个。

  ② 非可引导（格式化成普通空盘）
     不写入任何镜像，只把磁盘重建为「单分区 + 指定文件系统」的普通磁盘。
       · 分区表：MBR（兼容老主板 / BIOS）或 GPT（UEFI 新主板）
       · 文件系统：FAT32 / NTFS / exFAT
       · 卷标：可留空（FAT32、exFAT 最多 11 字符，NTFS 最多 32）
       · 快速格式化或完整格式化（逐扇区扫描坏块）
     用途：把被镜像写过、Windows 认不出的 U 盘恢复成能正常读写的普通 U 盘。


【刻录中途失败（错误码 5）已在 v1.2.6 修复】

  根因：镜像自带分区表，第 1 块就把 U 盘旧分区表覆盖掉，Windows 随即把镜像里
  的新分区挂载成卷；而 Windows 拒绝向「任何已挂载卷的第一个扇区」做裸写入。

  修复：写盘前先清除目标盘分区表；把含分区表的首块推迟到整盘最后写入；
  出错时关闭并重开物理磁盘句柄再重试。
  实测：3.08GB ISO 整盘刻录成功，读回 SHA256 与源镜像完全一致。


【怎么确认你用的是新版】

  · 程序底栏显示 v1.2.12；
  · 选一个 25H2 的镜像，识别结果应显示「Windows 11 25H2」而不是 24H2；
  · 识别结果下方「识别依据」应写明 sources/INSTALL.WIM → 系统映像 …；
  · 双击「查看当前版本.cmd」，会列出绿色版和安装版两处脚本的版本标记。

【先搞清楚：ISO 刻录后 U 盘「看起来坏了」是正常的】

  ISO 刻录是用镜像自带的文件系统（ISO9660/UDF）整盘覆盖 U 盘原来的 NTFS/exFAT。
  刻完之后 Windows 认不出这个文件系统，就会显示「需要格式化 / RAW / 未知容量」。
  Rufus、Etcher 烧任何 Linux ISO 都是这个结果，不是 U 盘被写坏。
  烧好的盘是「可启动盘」，不是「能往里拷文件的普通 U 盘」。

  · 想把 U 盘变回普通盘：用「非可引导」模式（或修复U盘脚本）。
  · 刻录完成后如果弹出「是否格式化」：点取消，不要格式化。


【刻录前请做这几件事（能避免大部分失败）】
  · 关闭所有停留在该 U 盘上的「此电脑 / 资源管理器」窗口。
  · 暂停杀毒软件的实时防护（360、火绒、Windows Defender 等）。
  · 不要打开「磁盘管理」或任何分区工具。
  · 插在机箱后面的 USB 口（直连主板），不要用前面板或 USB Hub。
  · 刻录过程中不要拔 U 盘。


【安全性说明】
  · 程序绝不会向系统盘（Windows 所在磁盘）写入，已加硬性拦截。
  · 写入前会校验：目标句柄确实指向你选的那块物理盘、镜像放得下。
  · 写入后会立刻从 U 盘读回并比对 SHA256，不一致会明确报错。
  · 镜像识别为纯只读操作，不会修改镜像，也不会访问磁盘设备。
