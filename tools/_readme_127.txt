Doro 镜像刻录工具 v1.2.7 —— 使用说明
=================================================


【本版新增：写入方式可选】

  首页「步骤 1」新增一个「写入方式」下拉框，目前两种模式：

  ① 整盘镜像刻录（DD 模式）
     把镜像（.iso / .img / .raw …）按字节原样写入磁盘，镜像自带的分区表、
     引导扇区、文件系统全盘照搬。做 Linux 启动盘用这个。

  ② 非可引导（格式化成普通空盘）
     不写入任何镜像，只把磁盘重建为「单分区 + 指定文件系统」的普通磁盘。
     可选参数：
       · 分区表：MBR（兼容老主板 / BIOS）或 GPT（UEFI 新主板）
       · 文件系统：FAT32 / NTFS / exFAT
       · 卷标：可留空（FAT32、exFAT 最多 11 字符，NTFS 最多 32）
       · 快速格式化（几秒）或完整格式化（逐扇区扫描坏块，大容量盘很慢）
     用途：把被镜像写过 / 认不出的 U 盘恢复成能正常读写的普通 U 盘，
     不用再去双击单独的修复脚本。

  选好模式后，下面的「目标磁盘」和「确认并开始」会自动切换成对应的选项与提示。


【刻录中途失败（错误码 5）已在 v1.2.6 修复】

  症状：整盘刻录时写到 1MB / 2MB / 6MB 处报「拒绝访问（错误码 5）」，
  刻录中断，U 盘停在半截状态。

  根因：镜像自带分区表，第 1 块就把 U 盘旧分区表覆盖掉，Windows 随即把镜像里
  的新分区（EFI 区正好从 2MB 起）挂载成卷；而 Windows 拒绝向「任何已挂载卷的
  第一个扇区」做裸写入 —— 报错偏移与该分区起始偏移完全一致。

  修复：写盘前先清除目标盘分区表；把含 MBR/GPT 分区表的首块推迟到整盘最后写入；
  出错时关闭并重开物理磁盘句柄再重试。
  实测：3.08GB ISO 整盘刻录成功，读回 SHA256 与源镜像完全一致。

【先搞清楚：ISO 刻录后 U 盘「看起来坏了」是正常的】

  ISO 刻录的原理是用镜像自带的文件系统（ISO9660/UDF）整盘覆盖 U 盘原来的
  NTFS/exFAT。刻完之后 Windows 认不出这个文件系统，就会显示「需要格式化 /
  RAW / 未知容量」。Rufus、Etcher 烧任何 Linux ISO 都是这个结果，
  不是 U 盘被写坏 —— 烧好的盘是「可启动盘」，不是「能往里拷文件的普通 U 盘」。

  · 想把 U 盘变回普通盘：用「非可引导」模式（或修复U盘脚本）。
  · 刻录完成后如果弹出「是否格式化」：点取消，不要格式化。


【刻录前请做这几件事（能避免大部分失败）】
  · 关闭所有停留在该 U 盘上的「此电脑 / 资源管理器」窗口。
  · 暂停杀毒软件的实时防护（360、火绒、Windows Defender 等）。
  · 不要打开「磁盘管理」或任何分区工具。
  · 插在机箱后面的 USB 口（直连主板），不要用前面板或 USB Hub。
  · 刻录过程中不要拔 U 盘。


【安全性说明】
  · 程序绝不会向系统盘（Windows 所在磁盘）写入，已加硬性拦截。
  · 写入前会校验：目标句柄确实指向你选的那块物理盘、镜像放得下。
  · 写入后会立刻从 U 盘读回并比对 SHA256，不一致会明确报错。
  · 任何内部异常都会中止并提示，不会带着未知状态继续写。
