Doro 镜像刻录工具 v1.2.16 —— 使用说明
=================================================


【本版改进：窗口做成一个整体，顶部不再有「两条栏」】

  ▸ 改之前长什么样

    窗口顶部是上下两条并排的栏：

      ┌──────────────────────────────────────────────┐
      │ Doro镜像刻录工具            ─   □   ✕        │  ← 系统标题栏
      ├──────────────────────────────────────────────┤
      │ (头像) Doro镜像刻录工具    v1.2.16 Windows … │  ← 程序自己的顶栏
      └──────────────────────────────────────────────┘

    两处还都写着同一个名字，看着重复、割裂，而且白占一行高度。

  ▸ 本版改成一条

    把系统标题栏藏起来，三个窗口按钮（最小化 / 最大化 / 关闭）改由系统叠画在
    程序顶栏的右侧，颜色跟着浅色 / 深色主题自动变。现在顶部只有一条：

      ┌──────────────────────────────────────────────┐
      │ (头像) Doro镜像刻录工具   v1.2.16 …   ─ □ ✕  │
      └──────────────────────────────────────────────┘

    少掉一整条标题栏，内容区反而多出一行的可视高度。

  ▸ 顺带的三处细节

    · 整条顶栏都是窗口拖动区：按住空白处就能拖动窗口，双击即最大化，
      和拖动普通标题栏的手感一致（按钮、下拉框照样能点）。
    · 右侧的状态标签（版本 / Windows / 管理员权限）和外观切换按钮会自动给
      窗口按钮让出位置，不会互相遮挡；窗口拉窄到最小时也不会被挤出去
      （此时那个副标题「跨平台镜像刻录 · Windows / macOS」会自动省略）。
    · 滚动条原本悬在内容卡片旁边，现在挪到窗口最右边 —— 整窗看起来才是一整块。
      内容依然是居中排版，位置没有变化。

  ▸ macOS 不受影响

    苹果系统继续使用原生标题栏与左侧红绿灯按钮，本版改动只作用于 Windows。


【上一版修复（v1.2.13）：Windows 10 22H2 曾被误判成 2004】

  ▸ 问题现象

    选一个 Windows 10 的镜像（文件名叫 Windows10-24H2.iso），识别结果却写
    「Windows 10 2004」，版本号 10.0.19041.3803，看着像是认错了版本。

  ▸ 原因（不是你的镜像有问题，是判断依据只能到这个粒度）

    Windows 10 的 2004 / 20H2 / 21H1 / 21H2 / 22H2 属于同一个「家族」，
    它们共用同一套系统内核。后果是：

      · 安装映像（sources\install.wim 或 install.esd）里写的版本号，
        这五个版本全都是同一个基础号 19041；
      · 安装盘里的 setup.exe 也只报这个基础号。

    真实版本号（装好系统后 winver 显示的那个，例如 19045）只写在映像内部的
    注册表里 —— 盘上读不到。所以「看到 19041 就说是 2004」这个做法是错的。

    实测你这张盘：install.esd 里写 <BUILD>19041</BUILD>，
    但修订号是 3803 —— 而 3803 对应的是 2023 年 12 月的补丁 KB5033372，
    那时 2004 / 20H2 / 21H1 早就停止更新了，只可能是 21H2 或 22H2。

  ▸ 修法：两步收窄

    ① 按修订号硬排除
       每个版本的首发修订号和终版修订号是公开固定的。修订号落在某版本的
       服役区间之外，就不可能是它。例：修订号 3803 直接排除
       2004（终版 1415）、20H2（终版 1706）、21H1（终版 2364）。

    ② 零售盘顺位
       零售盘（不带企业版版次的那种）只会发行「当时最新」的那一版。
       修订号 3803 ≥ 22H2 的首发修订号 2130，而这张盘带的是
       家庭版 / 家庭单语言版 / 教育版 / 专业版（零售盘版次）→ 判定为 22H2。

    于是这张盘的识别结果变成：

      Windows 10 22H2       版本 10.0.19045.3803       置信度 85%
      识别依据：sources/INSTALL.ESD → 系统映像：盘内写 10.0.19041.3803 ·
                零售盘只发行当时最新版：修订号 3803 ≥ Windows 10 22H2 首发 2130

    「识别详情」里还会多一行「盘内记录版本 10.0.19041.3803（19041 是家族共用
    基础号）」，把盘里到底写了什么说清楚，方便你自己核对。

  ▸ 收窄不到唯一答案时，如实说

    企业版（VL）媒体不做第 ② 步，因为企业版盘上 21H2 和 22H2 都可能带着同一个
    高修订号。这种情况系统名称会写成「Windows 10 21H2 / 22H2」，置信度 60%，
    并用一行提示说明原因 —— 不硬猜成同族里最老的那一版。

  ▸ 同一套判定也覆盖 Windows 11

    Windows 11 的 22H2 / 23H2 是同样的关系（官方 23H2 的盘里写的也是 22621，
    不是 22631），现在也能按修订号 + 版次正确判到 23H2。

  ▸ 顺带：文件名和镜像内容不符时会提醒

      「Windows10-24H2.iso」这个名字其实对不上任何真实版本 ——
      Windows 10 的最后一个版本是 22H2，并没有 24H2（那是 Windows 11 的版本号）。
      现在遇到这种「改名盘」会在识别结果下面提示一句：

        文件名里的 24H2 与镜像内容不符：这张盘实际是 Windows 10 22H2，
        请以镜像内容为准。

      文件名可以随便改，镜像是改不了的 —— 本工具一直以镜像内容为准。


【上一版修复（v1.2.12）：Windows 11 25H2 曾被误判成 24H2】

  同一个坑族的另一个面：25H2 / 23H2 属「启封包」版本，与基础版 24H2 / 22H2
  共用二进制，安装盘里连 setup.exe 都只报基础内核号 10.0.26100.x。

  修法：改读 install.wim / install.esd 内部映像写的真实版本号
  （25H2 的盘里写的就是 26200），识别依据会写明
  「sources/INSTALL.WIM → 系统映像 10.0.26200.8037」。

  实测你的 25H2 官方盘：识别为 Windows 11 25H2 | 10.0.26200.8037 | 98%。
  读不到系统映像时（自制盘、精简盘），如实标成「Windows 11 24H2 / 25H2」、
  置信度降到 55%，并说明原因，不硬猜。

  另外：读系统映像只读文件末尾的版本信息，不会把整个 install.wim（有的超过
  7GB）读进内存，识别耗时仍在毫秒级，不占内存、不动磁盘。

【历史修复（v1.2.11）：以管理员重启后不再多出一个窗口】

  点「以管理员重启」，新窗口起来了，但原来那个没有管理员权限的旧窗口
  还留在那儿，变成两个窗口叠着，分不清该操作哪一个。

  原因是程序没有单实例保护，提权后新旧两个进程各管各的。现在加了单实例锁：

    · 提权成功 → 旧窗口自动关闭，只留下带管理员权限的那个；
    · 用户取消 UAC 或提权被拒 → 旧窗口保持不动，并给出提示，不会白关；
    · 重复双击图标 → 不会再开第二个窗口，而是把已有的窗口提到前面；
    · 正在刻录时点提权 → 不会自动关窗口，避免打断写入。


【界面顺序、自动选写入方式、深色模式（v1.2.9 新增）】

  ▸ 镜像的识别结果在「写入方式」上面

    先看清「这是什么系统的镜像」，再决定「怎么写到 U 盘」。如果只想把磁盘
    恢复成普通空盘，第 1 步的镜像可以直接不选（此时会显示一句提示）。

  ▸ 按识别结果自动选择写入方式

    识别完成后，「模式」会自动帮你选好，并在下面标一个「自动」标签说明理由：

      · 镜像含引导信息（UEFI / BIOS ISOLINUX / Windows 引导）
          → 自动选「整盘镜像刻录」，这是做启动盘的正确做法

      · 镜像未检测到引导信息（例如 virtio 驱动盘、纯数据光盘）
          → 自动切到「非可引导（格式化）」，把 U 盘变成能正常读写的普通盘

    注意：非可引导模式不会写入镜像内容，只会把磁盘格式化。如果你其实是想把
    镜像里的文件放进 U 盘，请在模式下拉框里手动改回「整盘镜像刻录」——
    一旦你手动改过，程序就不会再自动覆盖你的选择。

    （后续版本的「ISO 模式（解包重排）」会把镜像内容解包后写进 FAT32 分区，
      那种做法才既能正常读写又能保留文件。当前版本请按需手动选择。）

  ▸ 深色模式

    右上角「外观」三态切换：

      自动（跟随系统）   跟着 Windows 的「浅色 / 深色」设置走，系统换它也跟着换
      浅色              始终浅色
      深色              始终深色

    偏好会记在本机，下次打开还是你选的那个；切换时窗口边框、窗口按钮、滚动条、
    右键菜单也会一起换色。启动前就已确定主题，不会先闪一下白底。


【自动识别镜像里的系统版本（v1.2.8 新增，后续版本持续增强）】

  在「步骤 1」选好镜像后，程序会立刻读取镜像内容，把里面的系统信息显示出来，
  不用再靠文件名猜。识别结果包括：

    · 系统名称与版本   例如 Windows 10 22H2、Ubuntu 24.04.3 LTS "Noble Numbat"
    · 内核/版本号      例如 Windows 10.0.19045.3803、Ubuntu 24.04.3
    · 处理器架构       x86_64 (64 位) / ARM64 / x86 (32 位)
    · 是否可引导，以及引导方式（UEFI / BIOS ISOLINUX / Windows 引导）
    · 卷标、镜像格式（ISO 9660 / Joliet / UDF）、镜像大小

  识别依据来自镜像内部的真实标记，不依赖文件名，改名也认得出来：

    Windows            优先读 install.wim / install.esd 里系统映像的版本号；
                       若写的是家族共用基础号（19041 / 22621），再按修订号与
                       媒体版次收窄，收窄不到唯一答案就如实列出可能的版本；
                       读不到时退回 setup.exe 版本 + idwbinfo.txt
    Ubuntu / Kali /
    Debian / 国产系统  读 .disk/info、README.diskdefines
    麒麟 / 统信 /
    RHEL / Fedora /
    Rocky / AlmaLinux  读 .treeinfo
    Arch / openSUSE /
    Alpine / ESXi      读卷标与目录特征

  说明：识别过程只读镜像文件，不碰磁盘设备，不需要管理员权限，通常几十毫秒完成。


【镜像格式说明：Windows 官方 ISO 的内容在 UDF 里】

  Windows 10/11 官方 ISO 为了让 install.wim 突破 4GB 限制，把内容全部放进了
  UDF 分区，ISO 9660 部分只剩下一个 README.TXT。本工具含 UDF 解析，
  所以这类镜像同样能正确识别。


【写入方式（v1.2.7 新增）】

  第 1 步的「写入方式」下拉框，两种模式：

  ① 整盘镜像刻录（DD 模式）
     把镜像按字节原样写入磁盘，镜像自带的分区表、引导扇区、文件系统全盘照搬。
     做 Linux 启动盘用这个。

  ② 非可引导（格式化成普通空盘）
     不写入任何镜像，只把磁盘重建为「单分区 + 指定文件系统」的普通磁盘。
       · 分区表：MBR（兼容老主板 / BIOS）或 GPT（UEFI 新主板）
       · 文件系统：FAT32 / NTFS / exFAT
       · 卷标：可留空（FAT32、exFAT 最多 11 字符，NTFS 最多 32）
       · 快速格式化或完整格式化（逐扇区扫描坏块）
     用途：把被镜像写过、Windows 认不出的 U 盘恢复成能正常读写的普通 U 盘。


【刻录中途失败（错误码 5）已在 v1.2.6 修复】

  根因：镜像自带分区表，第 1 块就把 U 盘旧分区表覆盖掉，Windows 随即把镜像里
  的新分区挂载成卷；而 Windows 拒绝向「任何已挂载卷的第一个扇区」做裸写入。

  修复：写盘前先清除目标盘分区表；把含分区表的首块推迟到整盘最后写入；
  出错时关闭并重开物理磁盘句柄再重试。
  实测：3.08GB ISO 整盘刻录成功，读回 SHA256 与源镜像完全一致。

【先搞清楚：ISO 刻录后 U 盘「看起来坏了」是正常的】

  ISO 刻录是用镜像自带的文件系统（ISO9660/UDF）整盘覆盖 U 盘原来的 NTFS/exFAT。
  刻完之后 Windows 认不出这个文件系统，就会显示「需要格式化 / RAW / 未知容量」。
  Rufus、Etcher 烧任何 Linux ISO 都是这个结果，不是 U 盘被写坏。
  烧好的盘是「可启动盘」，不是「能往里拷文件的普通 U 盘」。

  · 想把 U 盘变回普通盘：用「非可引导」模式（或修复U盘脚本）。
  · 刻录完成后如果弹出「是否格式化」：点取消，不要格式化。


【刻录前请做这几件事（能避免大部分失败）】
  · 关闭所有停留在该 U 盘上的「此电脑 / 资源管理器」窗口。
  · 暂停杀毒软件的实时防护（360、火绒、Windows Defender 等）。
  · 不要打开「磁盘管理」或任何分区工具。
  · 插在机箱后面的 USB 口（直连主板），不要用前面板或 USB Hub。
  · 刻录过程中不要拔 U 盘。


【安全性说明】
  · 程序绝不会向系统盘（Windows 所在磁盘）写入，已加硬性拦截。
  · 写入前会校验：目标句柄确实指向你选的那块物理盘、镜像放得下。
  · 写入后会立刻从 U 盘读回并比对 SHA256，不一致会明确报错。
  · 镜像识别为纯只读操作，不会修改镜像，也不会访问磁盘设备。
